加载态 首次打开，还在拉材料

打开到材料出现之间。**材料列表没回来之前，整屏都是骨架**——包括小问的常驻条。 这样用户第一眼看到的是"正在来"，而不是一块空白。
🙋
小问正在来…
加载中
讲讲你的理解…
↑
  • 骨架屏用**灰块脉动**（1.4s 循环），不用转圈——转圈在手机上显得卡
  • 输入框**置灰禁用**（发送键变浅灰），这时点不动
  • 超时：超过 20s 没回来 → 转 错误态 A
为什么整屏骨架：只让材料条转圈、小问条却亮着，会显得页面"半坏"。统一骨架更干净。

  • 2.1 全空：topics 返回空数组。**没有"换个材料"按钮**——没得换，别给死路。输入框禁用
  • 2.2 待讲为 0：材料还有，只是都被"讲过了"。**当前材料照常留着**（还能重讲），面板里"还没讲的"区**整块不出现**

部分可用 拿到一半，别整屏崩

后端可能返回"材料有，但某篇正文是空的/坏的"。**坏一篇，不能坏整屏。**
🙋
小问我记住 1 个了，你挑一个接着讲
什么是 RAG？
换个材料展开
这篇的正文没读到，你可以先讲你记得的。
诶，你刚看的那篇讲啥的？
讲讲你的理解…
↑
  • 正文缺失 → 材料条里显示一行温和提示，**对话照常**（她还是能听你讲）
  • 某条材料的标题缺 → 用「未命名材料」兜底，不显示 undefined
  • 面板里"小问记住了"某条缺总结 → 只显示标题，不显示空引号
原则：能降级的都降级，别把技术故障摊到用户脸上。

边界情况 长得丑的地方，先定好

情况会怎样怎么处理
超长标题 材料条被撑爆，按钮被挤出去 材料条标题**单行省略号**（text-overflow:ellipsis），按钮固定不缩
超长正文 材料条展开后占满全屏，对话没了 展开区最高 38dvh，**内部滚动**
超长对话 翻到很早以前，输入框跟着滚走 输入框**钉在视口底部**，只有对话区滚
话题很多（几十条） 面板列表拉不完 面板最高 80dvh **内部滚动**；主界面**永远只有一张材料**，与总量无关
用户一次发一大段 输入框要么被撑高毁布局，要么看不全 输入框**单行**，最多 3 行后内部滚动（同微信）
快速连点发送 同一句发两遍 / 请求打架 发送中**禁用输入与按钮**，请求返回才解锁
她"想"太久 「小问正在听…」一直转 超 20s → 转 4.2 发言失败（可重试）
她说的复述很长 气泡超过 80% 宽，糊成一片 气泡限宽 80%，自动换行
总结为空 面板里出现「」两个空引号 总结为空 → **不进"小问记住了"**，当作没懂

Toast 刻意只有两条

这个产品的铁律是不打扰。所以不搞成功 Toast（"保存成功！"这种）， 只有**真的失败了、且用户能自己救**的场景才提示。
场景文案形式 / 位置时长
发言发不出去 没发出去 · 重试 **对话流内**提示条（非浮层） 常驻到重试成功
服务连不上 没能拿到材料。检查下服务是不是没启动。 **整屏空态**（非浮层） 常驻到重试成功
记忆没写进盘 不提示——静默降级。存储层的事不摊给用户
她"懂了" 不提示——用她开口复述来表达，不用系统弹条
规则：Toast 位置统一在**输入框上方**（拇指区，不遮内容）；错误类不自动消失； 同时最多 1 条（本产品不存在并发错误的场景）。

规则表 前端照这张表实现

触发用户操作系统行为反馈
用户首次打开页面 GET /api/topics + GET 记忆（按设备 id） 整屏骨架 → 成功渲染；失败转 4.1
（加载超 20s）中止请求转 4.1 错误态
用户点材料条「收起 / 展开」 切换正文可见性正文高度 0.3s 过渡；按钮文案在「收起 / 展开」间切
用户点「换个材料」或小问头像 打开面板，渲染两区：还没讲的 / 小问记住了 面板从底部升起 0.26s
面板里点某张材料 设为当前材料 → **不产生任何消息** 面板收起；新材料展开正文、讲过的收起；输入框聚焦
点面板外 / ✕关闭面板面板下滑收起
面板里「还没讲的」为 0不渲染该区只剩「小问记住了」
用户输入文字 —输入框获焦边框变珊瑚色；空内容时发送键不可点
点发送 / 回车 ① 用户消息上屏 ② 材料条自动收起 ③ 禁用输入与发送 ④ 显示「小问正在听…」 ⑤ POST /api/chat 「小问正在听…」打在对话流末尾
（请求成功） 移除加载中 → 追加她的回复 → 解锁输入 → 聚焦 她的话以气泡出现
（请求失败/超时） 移除加载中 → 保留用户那条 → 追加可重试提示条 见 4.2
系统（后端判定"她懂了"） ① 剥离隐藏标记 ② 生成一句口语化总结 ③ 写记忆 ④ 返回正文 她回复里出现复述确认（用户感知不到标记与总结过程）
（记忆写入成功）刷新前端记忆状态 顶部「我记住 N 个了」+1；该材料移入面板「小问记住了」
（记忆写入失败）丢弃这次的记忆更新，对话照常返回 静默——用户察觉不到
（总结为空）当作"还没懂"，不写记忆静默
异常（网络断 / 服务停） 按 4.1 / 4.2 就地提示，不跳页、不弹窗 见错误态
异常（单篇正文坏了） 该材料降级展示见 5 部分可用

映射 什么数据驱动什么状态

界面元素由什么决定
小问常驻条那句话 记忆条数 N：N=0 →「我还不懂这些，你挑一个讲给我听」；N>0 →「我记住 N 个了，你挑一个接着讲」
材料条标题当前材料的 title（单行省略）
材料条展开 / 收起 默认：未讲过的 = 展开，讲过的 = 收起；用户一发送就强制收起（本次会话内不再自动展开）
面板「还没讲的」记忆里没有的材料，按原顺序
面板「小问记住了」记忆里有 summary 的材料，显示 title + summary
空态 2.2还没讲的 == 0 且 材料总数 > 0
空态 2.1材料总数 == 0
材料条里的降级提示当前材料的 content 为空
「当前」标签面板项 id == 当前材料 id
记忆数据结构（V0.3 · 后端 memory.json）
{ "<设备id>": { "<材料id>": { "summary": "给它一个目标，它自己拆步骤去干", "at": "2026-10-10" } } }
只存"讲过的 + 她记住的那句话"。**不存完整对话历史**——V0.3 用不着，留着以后再说。
