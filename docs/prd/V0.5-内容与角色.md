# V0.5 内容与角色 · 讲给朋友听

> 单版本 PRD：**一轮迭代里做了三件事**——内容形态 / 会话分段 / 角色定位
> 版本状态：🔄 主体完成（2026-10-11），待用户长期体感验证
> 来源：V0.4 交付后用户连续实测，三轮反馈
> 改动落在：`app/topics.json`、`app/chat.py`、`app/web.py`、`app/static/index.html`

## 版本核心目标

V0.4 解决的是"**她给不给你东西**"。这一版解决 V0.4 之后实测撞出来的另外三件事：

| # | 用户原话 | 问题 | 本版做法 |
|---|---|---|---|
| 1 | "**内容确实干**，什么是 Agent 然后对着讲" | 标题没钩子 | 钩子标题 + 正文给回答案 + 点出名词 |
| 2 | "**历史对话不能都在一个窗口里，我觉得有些乱**" | 全堆在一条流里 | 一条材料一段对话 + 左侧抽屉导航 |
| 3 | "**我的问题没有得到立刻解答**……让我去教小问好像不太合适" | 她装不懂、不直接答 | 她懂行、直接答；去掉"教"这层关系 |

## 一、内容形态：钩子标题 + 给回答案

### 1.1 起因

用户："**内容确实干，什么是 Agent 然后对着讲，内容后面一定要升级**"。

### 1.2 走过的一段弯路（⚠️ 记下来，别重犯）

**第一版做法：「给一半留一半」——材料只给事实，不给结论。**

理由听起来成立：原来材料是完整答案（定义 + 例子 + 结论），用户只能**复述**，而复述没快感。

**实测当场被推翻。** 用户原话：

> "咱讨论教小问这个方向对不对，根据这个材料，应该是**我知道**，有点考问小问的意思，但**用户本身是不知道的**，这样的材料反而弄的用户不明白了，但我觉得这个材料还是挺吸引人的……**我也不知道为什么差这么多，我还是要教小问的，我感觉挺别扭的**"

**为什么错**（这段最重要）：

- 产品的根是**费曼技巧**：你学过了 → 讲给别人 → **在讲的过程中**发现自己哪里没讲明白
- "发现自己没懂"是**讲出来的后果**，不是材料的坑。**我把"后果"提前做成了"前提"**
- 而且材料末尾那句"小问：……？"更糟——**她一开口就是在考用户的知识，而用户知道的跟她一样少**

**拆开成两件事**（关键）：

| | 治什么 | 结论 |
|---|---|---|
| **钩子标题** | 治"内容干" | ✅ **留**——真治好了（用户："这个材料还是挺吸引人的"） |
| **正文留白** | 本想治"复述"；但复述从来不是问题（V0.4 已经治了"没粘性"） | ❌ **去掉** |

### 1.3 最终形态

**钩子标题 → 现象 → 对照 → 答案 → 末尾点出名词**

用户补的要求："**你说的正文有答案，得把名词点出来吧**"——读完得知道这东西叫什么。

例（提示词）：

```
[AI 名词] 你少说两句，它多写三页废话

你跟 AI 说「帮我写个总结」，它给你一坨。

你要是说「把这份记录压成五条要点，每条不超过二十个字」，它给的就能直接用了。

同一件事，只是你多说了一句话。

说白了就一条：它看不到你脑子里那一版。你写得越具体，它猜的余地越小，给的就越接近你要的。

你发给它的那段话，就叫提示词（Prompt）。
```

### 1.4 改造清单

- **10 条材料全部重写**：`title` 换成钩子式、`content` 给回完整答案、末尾点出名词
- 每条新增 **`name`**（短名：Agent / RAG / 幻觉 / …）——标题变长且不带「」后，
  `shortName()` 会抠出**整句**，开场白会变成
  *"上次你跟我讲那个我只说了一句话它自己把活干完了"*
- 材料条加 **「AI 名词」标签**（用的是 topics.json 里一直有、前端却没用的 `type` 字段）
  —— 用户："**不然用户不知道往AI方面想**"
- `ask` 字段（"小问：……？"）**废弃**，渲染代码和 CSS 一并删掉

### ⚠️ 设计上守住的那条分界线

万一以后再想"留白"：**留下的那一半，必须是他自己归纳得出来的一步，不能是需要额外知识的一步。**
否则就不是练表达，是考知识——产品命题"**他听懂了**，你就讲明白了"里，"他听懂了"是前提。

## 二、会话分段（甲方案）

### 2.1 起因

用户："**历史对话不能都在一个窗口里，我觉得有些乱。**可以侧边加上新建会话……
**但是和10条材料，以及后面的材料怎么协调排布你好好想想**"

### 2.2 跟 V0.3 那条决策顶着

V0.3 定过：**对话只有一条，换材料不清空**。理由是
"把对话装进卡片，会长成**三个小问，各记各的**"。

### 2.3 解法

**V0.3 怕的是"有多个小问"。而它怕的根源是"记忆各记各的"。**
现在的记忆是**全局的**（`memory.json` 按设备存，不分材料）——
**不管翻到哪一段，她都知道你聊过的一切。**

所以：**小问始终是一个（记忆共享），但聊天可以分成很多段。**

给了三个方案，用户选**甲**：

| 方案 | 做法 | 结果 |
|---|---|---|
| **甲：按材料分段** | 侧边（左侧抽屉）= 材料列表 = 段导航 | ✅ **采纳** |
| 乙：ChatGPT 式 | 会话与材料脱钩，自己起名自己管 | ❌ |
| 丙：一条流 + 分隔 | 同一条对话，换材料插分隔线 | ❌ |

**甲的要点**：点哪段显示哪段（不用滚）；她递下一张材料 → 自动切到新一段；
**列表本身就是"新建入口"**（点"还没讲的"里任意一条 = 开一段新的）。

### 2.4 数据结构

```json
// history.json（旧）
{ "<设备id>": {"topic": "<材料id>", "messages": [...]} }
// history.json（新）
{ "<设备id>": {"cur": "<材料id>", "sessions": {"<材料id>": {"messages": [...], "at": "..."}}} }
```

与 `memory.json` 结构对称。`GET /api/history` 返回 `{cur, sessions}`；
`POST /api/chat` 不变（本来就收 `topic_id`）。

### 2.5 改动清单

| 文件 | 改动 |
|---|---|
| `app/web.py` | `GET /api/history` 返回 `{cur, sessions}`；`POST /api/chat` 存进 `sessions[topic_id]` |
| `app/static/index.html` | 新增 `sessions` / `sessionOf()` / `renderChat()`；`pick()` 从"换材料条"改成"**切段**"；`boot` 恢复多会话；`.sheet.side` 左侧抽屉 CSS |

⚠️ **一个必须守住的坑**：`sendText` 里存回复用的是**局部 `seg`**，不是全局 `history`。
否则用户等她回复时切走，她的话会**串到另一段**去。

### 2.6 数据清理

用户要求"重新开始"。`memory.json` / `history.json` **都备份为 `.bak` 后清空**：

- 清历史是用户明确要的
- **清记忆是我建议的**：不清的话 10 条材料全走 A8（"这个你跟我讲过"），测不出新形态
- 清空前先看过内容：1 台设备，学过 5 条（prompt / temperature / multimodal / context / agent）

## 三、角色定位：她懂行，且不再提「教」

### 3.1 起因

用户甩来手机截图，原话：

> "角色我觉得对换一下更好，**小问是知识渊博的老师**，会耐心温和的解答用户的疑问，
> 引导用户理解透概念，因为现在双方的感觉不大对劲……**我的问题没有得到立刻解答**，
> 这让我觉得让我去教小问好像不太合适，小问应该能帮我**快速理清我困惑的点、说不清楚的点**，
> 而不是把她教明白"

截图里逐句暴露的问题：

| 她说的 | 毛病 |
|---|---|
| "哦哦**我懂了**——就是……" | 用户在**问**，她在**宣布自己懂了** |
| "我刚才是**看你材料里写了**…才问的" | 甩材料（用户："我没看材料吗？"） |
| "这个你跟我讲过…**跟我记的不太一样**" | 用户在问，她扯记忆，还坚持己见 |
| "哦，**那我直接跟你说**。" | 白加一层客套过渡 |
| "那你要不给我讲讲 Agent？" | 用户还在追问，她就递材料 |

### 3.2 根因：**不是她不会答，是提示词不让她答**

同一张截图里，最后一条她答得**极好**：

> "一般说训练是从零教起，它这会儿早训完了，再喂你的数据只是稍微拧拧脑子里的参数，
> 改动很小，所以叫微调。就像大学毕业后去个短期培训班，也是上课，
> 但谁也不会说那是重读大学。"

代码一对照就清楚了：提示词里"**她不懂**"这个设定**出现了三次**
（【你是谁】/【参考材料】/行为8），而"要帮上忙"只有一次。**权重完全反了。**

### 3.3 判断：不是"角色对换"，是"她本来就懂，只是不让她说"

⚠️ **必须记住的 trade-off**——完全对换成"什么都答的老师"，
`方向讨论与竞品对比.md` 第三节那张表会**整个塌掉**：

| 维度 | 豆包 | 我们 |
|---|---|---|
| 角色 | 有问必答的**专家** | 不懂的人 |
| 用户位置 | 提问者、被服务者 | **讲的人** |
| 给用户的 | 答案 | **"我说明白了吗"的验证** |

那份文档里还有一句很硬的话：**"把我们的系统提示词贴给豆包，效果能到九成。"**

**所以保留的那一条**：用户讲给她听时，她用一个"**没接触过的人能不能跟上**"的标准，
帮他挑没说清楚的地方（她懂行，所以挑得准）。

**现在的分工**：

```
有疑问 → 问她 → 直接、耐心答            ← 本版新增
觉得懂了 → 讲一遍给她 → 她挑你的漏洞     ← 产品核心，保留
```

### 3.4 改动清单（`app/chat.py`）

**第一轮**

- 【你是谁】："这个话题的材料你也扫过一眼，但没真搞懂" → **"这些概念你都懂"**；
  加"**他问你的时候直接、耐心地答**"
- 【参考材料】："（你也扫过，但你记得的只是几个零碎的词）" → **"这是他的起点，不是你的知识边界"**
- 【最重要】新增三条禁止：**甩材料 / 反问"你觉得呢" / 要求他先讲一遍**
- 行为 8 开头："你确实没学过这个话题" → **"这些概念你本来就懂"**
- 递材料时机：新增 **"他在求答案时绝对不递"**
- `review_block`：新增 **"先分清他在干嘛"**（他在**问** → 先答问题；他在**讲** → 才按记忆规则走）

**第二轮**

- **客套开场去掉**：删掉硬性规定的"哦哦我懂了——"，改成直接说内容；示例同步改；
  新增禁**过渡话**（"哦，那我直接跟你说""行，我来告诉你"）
- **"教"字全部拿掉（5 处）**：

| 位置 | 改前 | 改后 |
|---|---|---|
| 记忆块标题 | 【你已经**知道**的】…是他一样一样**教**给你的 | 【你们以前**聊**过的】 |
| 记忆用法示例 | "跟上次你**教**的 XX 是一个道理" | "诶，这个**咱们聊过**——跟 XX 是一个道理吧" |
| 搭桥示例 | "你之前**教**我 RAG 是翻书" | "你之前**跟我讲** RAG 是翻书" |
| 开场白（3 句里 2 句） | "上次你**教**我那个 X" | "上次你**跟我讲**那个 X" |
| 侧栏分区 + 她的话 | 「你**教**给她的」/ "这些是你**教**我的" | 「**你跟她讲过的**」/ "这些都是你**跟我讲过的**" |

- 新增硬规矩：**绝对不许说"你教我的""你教过我""我跟你学的"**
- 新增：**他说"我没说过""我不记得"时别跟他争**，顺一句"那可能是我记岔了"就拉回正题

### 3.5 实测

```
问：微调就是给模型上辅导课吗？训练完后在灌输一些知识？
答：上辅导课这比喻挺准。但说白了不是训完硬灌，是拿你的数据再练一遍，
    把东西揉进它脑子里，以后不靠翻资料自己就会了。

问：把文字转换成数学向量，意思越近的词在坐标轴里位置越靠近？
答：对，就这意思——文字变一串数，意思越近就挨得近，不用死磕字面。
    咱们之前聊的 RAG，去资料库搜那步底层靠的不就是它么，按意思找而不是对字。
```

✅ 直接答　✅ 无"哦哦我懂了"　✅ 用"**咱们之前聊的**"而非"你教我的"

### 3.6 ⚠️ 用户自己推翻的一条（记下来，别重犯）

用户说向量那条材料"链路讲得不清楚"，要求她把完整链路讲出来；**紧接着自己补了一句**：

> "（等下，**这应该是由用户总结出来是吧**，那这样的话就没问题了）"

→ **完整的链路本来就该由用户说出来**，她讲全了反而没用户什么事。**这条不用改。**

## 五、未完成 / 遗留

- ⭐ **用户长期体感验证**——本版（乃至整个产品）唯一的成败判据
- **面板标题「小问的学习本」**：功能已变成"段导航"，**是否改名待定**
- **服务部署**：现在整个服务跑在用户自己电脑上，电脑一关手机就打不开（老问题，见 PRD_REGISTRY）
- **换 TTFT 低的模型**：最能改善"她反应慢"的一件事（V0.4 遗留）
- **联网搜索**：留到做"现象热点"时一起做（V0.4 遗留）
- 音色：`501000` / `501002` 两个候选的性别未确认

## 六、走过但不做（留档）

- ❌ **材料正文留白**（"给一半留一半"）——见 1.2，实测当场推翻
- ❌ **完全对换成"什么都答的老师"**——会丢掉跟豆包的差异，见 3.3
- ❌ **动画 / 动态效果**——用户问过，结论是不加（不解决"想再回来"，且与"界面简洁"打架；
  已有的打字机 / 递材料卡延迟**保留**，它们是节奏控制不是装饰）
