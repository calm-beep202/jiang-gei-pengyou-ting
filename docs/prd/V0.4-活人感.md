# V0.4 活人感 · 讲给朋友听

> 单版本 PRD：诊断 + 决策 + 改动
> 版本状态：🔄 进行中（2026-10-10 起）
> 来源：用户实测 V0.3 后的反馈 → 一次完整的"思考拍档"推演
> 配套：本轮全在 `app/chat.py`（提示词）+ `app/static/index.html`，**未改数据结构**

## 版本核心目标

V0.3 做完了记忆——**机制全通，但产品不成立**：

> 用户原话："我讲给小问听，她听懂了并记了下来，我讲了 10 个她记下来 10 个，
> **我目前没有感觉到这款产品吸引我的点**，无非就是一个点我讲给一个人听，讨论完之后对方懂了。
> 这里面我没体会到有多少爽感，也没有多少想二次打开的欲望。"

所以 V0.4 只做一件事：**让她给你东西。**

**明确不做**：内容升级（V0.5）、拟人形象/二次元立绘、多个朋友、等级/打卡。

## 一、核心诊断（**这一节最重要，别丢**）

### 1.1 问题：这个互动里，用户只出不进

```
你 ──讲──→ 小问 ──追问
你 ──讲──→ 小问 ──复述确认
你 ──讲──→ 小问 ──记住
                    ↑ 全是她收下的，她一件东西都没回给你
```

用户列出的三个"会想再打开"的产品，**每一个都在给他东西**：

| 产品 | 给什么 |
|---|---|
| 抖音 / B站 / 起点 | **内容**——每刷一下都有新的 |
| 不背单词 | **舒适**——每屏都干净顺眼，不堆装饰 |
| 多邻国 | **角色**——多儿有脾气、有情绪、说的是人话 |

小问给的是"哦哦我懂了"——**那不是东西，是回执**。单向付出，谁都会枯竭。

**这解释了全部两个感受**：
- "没爽感" → 她没给你东西，只给你回执
- "不想再打开" → 她那边没有任何值得期待的东西

### 1.2 根因：这是 V0.2 **修出来的**

V0.2 实测跑偏成"段子手"，于是下了三条禁令：禁 emoji、禁俚语、**禁吐槽抖机灵、禁发表评论、禁评价用户**。

**这三条修对了 bug，但顺手把她的人格一起砍了。**

砍完之后她只剩两个动作：**追问**（向你要东西）和**复述**（把东西还给你）。
**没有情绪、没有偏好、没有故事、没有观点、没有小脾气。**
→ 她不是朋友，是一台**"确认机"**。

### 1.3 卡点：铁律禁的是"姿态"，不是"她有自己"

用户检查了自己定的铁律，发现**一条都没禁止她"给"**：

| 定的规矩 | 真正禁的 | **没**禁的 |
|---|---|---|
| 不评价用户 | "你说得很清楚"这种**判词** | 她**自己**的感受（"你这么一说我就懂了"） |
| 不打分 | 给用户的表达打分 | 说**她自己的**事 |
| 不打扰 | 主动来敲门催你 | **当面**时她有自己的东西 |
| 不点明师徒 | 贴"师父/徒弟"的标签 | 她有自己的脾气和喜好 |

**用户想禁的是"她摆出考官/老师的姿态"，但顺手把"她有自己"也一起禁了。**

## 二、关键决策

| # | 决策 | 原因 |
|---|---|---|
| A1 | **她脑子清楚，甚至比一般人清楚** | ⚠️ **推翻了初版设想**。我起初想做"她会犯错，等你纠正"，用户否掉：**她笨的话，"她听不懂"就变成她的问题**，而产品命题"他听懂了，你就讲明白了"要求**她的不懂必须能反映你的表达**。她笨，这个映射就断了 |
| A2 | **她不好糊弄**——你讲得糊，她当场指出哪一步断了 | 这同时治了"她永远会懂，所以'懂了'不值钱"。根因是 V0.2 写的「门槛别太高，意思到位就该懂」——**是为了不给人压力，但结果把她变得太好糊弄** |
| A3 | ⚠️ 但**判的是"意思传到没传到"，不是"说得漂不漂亮"** | 不要求用户有逻辑/结构/金句——只要求真的说明白了。这两件事差很远 |
| A4 | **她可以真夸**（"你讲得挺清楚的"） | 用户主动松了 V0.2 的禁令。但要**真的才说**，不能当口头禅——**因为她的批评是真的，她的表扬才值钱** |
| A5 | **她会"用出来"，不是空问** | 分界线：**比得有没有内容**。说得出"它俩哪儿像" → 说；说不出 → 硬凑，别提。空问"这俩是一回事吗"最蠢 |
| A6 | **她带着记忆开口** | 最狠的一下——在你**还没说话**时就证明"她变了"。可以做多个说法随机，免得天天一样。**不违反铁律**（陈述自己状态 ≠ 等你/催你） |
| A7 | **成长轨迹的主语必须是"你"** | 现在显示「小问记住了（10）」是**她的收藏夹**；改成「**你教给她的**」——同一份数据，主语一换，归属就变 |
| A8 | 记忆和"不好糊弄"的冲突 → **按 A 解**（她明说"这个我记得"，把重讲变成复习） | 已发现未实现：她已有记忆时，会拿记忆把用户没讲清的地方自己补上，**门槛又被拉低**。⚠️ **本版待办** |
| A9 | **不一定都要用户先讲**——用户不想讲/没看懂时，他可以**直接问她**，她得陪他搞懂 | ⚠️ **用户实测反馈**：原设计她一被问就说"材料不是你看的吗，你先念念"——**很欠揍**。产品不该只有"我讲给她听"一条路 |
| A10 | ⚠️ 但 A9 **不是**让她变成讲解机 | 她**不直接倒答案**（那跟豆包没区别）。她做的是：用**他教过的东西**搭桥 → 把扫到的零碎抛出来一起看 → 一步步来 → **最后永远收在"那你现在说说看？"**。核心命题没丢，只是入口多了一条 |
| A11 | 人设改一字：**"假装没看过" → "扫过一眼，但没搞懂"** | 原来的"你假装没看过"导致她一被问就推回去。改成"扫过但没懂"——她既能**给线索**（记得几个零碎词），又保住了"不懂的朋友"（她确实串不起来） |
| A12 | ⚠️ **用户问事时，绝对不许扯无关的记忆** | ⚠️ **用户实测反馈原话**："我都问你了什么是微调了，你还说温度的事"——**记忆是背景，不是话头** |
| A13 | ⚠️ **她不能死守材料**——材料**不是**她唯一的信息来源 | ⚠️ **用户手机截图暴露**：她整场都在问"你材料里还咋说的？"，用户说"我也不知道了"她还来一句"那你现在说说看？"。**这是把球踢回给一个空着手的人。** 她本来就是聪明人，有常识、会推理、会打比方——是我在提示词里把她压死了 |
| A14 | ⚠️ **"让他自己讲一遍"不是每轮都必须收在那句上** | 同上截图。用户明显在求解答（连着追问、"我也不知道了""你就直说吧"）时，**讲完就讲完**，别再补"那你现在说说看"——那时候说这个就是推卸 |
| A15 | **对话历史要持久化**（按设备，存后端） | ⚠️ 用户反馈："我在浏览器重新打开页面后对话记录都没了"。同时要把**上次聊的是哪张材料**也存下来，否则恢复后材料条会跑偏 |
| A16 | **联网搜索：调研后决定暂不做** | 见下方"关于联网" |
| A17 | ⚠️ **一条回复里最多一个"要他做的事"** | ⚠️ **用户手机截图暴露**：她一口气干了三件事（复述 + 追问时间轴 + 递 Token 材料），**用户不知道该先回哪个**。规矩改成：要么问一个问题，要么收尾去讲下一张。**递的那一条里不要再夹追问** |
| A18 | **问候隔 6 小时才补一次** | "有历史就不重说开场白"解决了啰嗦，但也让 A6 废了。折中：**隔了较久才补一句**（前端记 `last_open`，超过 6 小时才问候） |
| A19 | **递材料卡延迟 1.2 秒淡入** | ⚠️ **用户反馈**："她的回答和卡片一块出来，我先看到下面的卡片，往上滑才能看到她的回答"。修法：她的话先上屏并滚到底，卡片慢一拍再滑进来（**后改为"她的话吐完 + 4 秒"**，见 A20） |
| A20 | **打字机效果**——她的字**平滑吐出来**，不是"啪"一下全出现 | ⚠️ **用户反馈**："文字出现的速度太快了，一下就看花眼了"。实测后端 78 个字 0.6 秒全到，前端一次性渲染。改成 ~24 字/秒；落后超过 80 字时才加速，免得长回复等太久 |
| A21 | **递材料卡的时机：她的话吐完 + 4 秒** | ⚠️ **用户反馈**："出来的还是有些快，等用户看完小问的话再思考一两秒比较好，整体 7-8 秒出来差不多"。现在典型回复（78 字）→ 吐字 3.3s + 停 4s = **7.3s** ✓ |
| A22 | **语音播报**（腾讯云 TTS，子账号） | 用户要求"活人感还需要加上语音说话功能，类似豆包的声音"。**浏览器自带 TTS 达不到**，所以接云端 |

## 语音播报（A22，2026-10-10 已实现）

### 架构：**按需请求**，静音零消耗

```
前端静音  →  根本不发 /api/tts  →  后端也不去调腾讯云  →  零消耗
```

⚠️ 这是**刻意选的**。另一种搭法（后端生成回复时顺手合成语音）**即使静音也会消耗额度**。用户专门问过这个问题。

### 服务

- **腾讯云语音合成**（产品 1073），用户已领"大模型音色"免费包（10 万字符 ≈ 1250 条）
- 走**子账号** key（只有 TTS 权限），`.env` 里 `TTS_SECRET_ID` / `TTS_SECRET_KEY`
- `app/tts.py`：手写 TC3-HMAC-SHA256 签名（不引第三方 SDK，保持零依赖）
- `POST /api/tts`：`{text, voice}` → 返回 `audio/mpeg` 二进制

### ⚠️ 音色：只有两个区段能用

实测 28 个候选，**13 个可用**，15 个报 `PkgExhausted`（不是"无权限"，是**资源包额度耗尽**）：

| 区段 | 结果 |
|---|---|
| `501000`–`501007`（智字辈） | ✅ 8 个 |
| `601008`–`601014`（爱字辈） | ✅ 5 个（文件大一倍，疑似更高音质档） |
| `4xxxx` / `502xxx` / `603xxx` | ❌ 全部 `PkgExhausted` |

**推测**：免费包**按音色等级分**，那批不在包内。要用别的音色得去控制台看额度怎么分。

### 交互

- 右上角**喇叭按钮** → 打开「她的声音」面板：**开关 + 13 个音色列表（每个带「试听」）**
- 选择存 `localStorage`；`/api/tts` 收 `voice` 参数（非 6 位数字一律忽略走默认）
- 语音和打字机**同时开始，不做严格对齐**（用户原话："豆包也是字出完了声音还在读"）
- iOS 自动播放限制：**第一次点发送时塞一段静音音频"解锁"**

### 关于用户自己提的两个方向（明确否决）

- ❌ **拟人化形象 / 二次元立绘**：解决的是"更想点开"，**不是"更想回来"**；而且开销大、会滑向养成游戏，与清淡基调冲突
- ❌ **多个朋友**（用户提过）：**现在别散**。一个小问都还没立住，加第二个只会稀释
- ⏸️ **毒舌吐槽**：用户说"可以保留作为**后面另一个朋友**的性格特点"——留档，不在本版

| 位置 | 改前 | 改后 |
|---|---|---|
| 【你是谁】 | "你有常识、会思考，不是傻子" | **"你脑子很清楚，逻辑正常，甚至比一般人还清楚一点"** + **"你没听懂，永远是因为对方没讲清楚，不是因为你笨"** |
| 【你怎么说话】 | 反应只有"啊？""真的假的""哦哦" | 加**情绪菜单**：惊讶 / 恍然 / 听懵了 / 追着问 / 觉得有意思 / 被绕烦了直说。约束：**清淡的活泼**，不吵、不刷存在感 |
| 【你怎么说话】 | "禁止评价用户的表达——一句都不要" | **松绑**：判词不说，但**感受可以说**；真的讲得好也可以直接说"你讲得挺清楚的"，**但得是真的** |
| 【你的行为】2 | "真有地方没听明白就追问" | **"你不好糊弄"** + 判断标准：**"一个没接触过、但脑子很清楚的人，听他刚才那段，能跟上吗？"** |
| 【你的行为】4 | "门槛别太高，意思到位就该懂" | **"你不挑漂不漂亮，但要求意思真的传到你这里"** + **"不许不懂装懂"** |
| 【你已经知道的】 | "大部分时候都别提"（⚠️ 这句权重太大，实测压住了正面行为，已重写） | **"你早就不是刚认识他那会儿的你了"** + 串起来的具体样子 + **分界线：比得有没有内容** |
| 【参考材料】 | "**你假装没看过**" | **"你也扫过，但记得的只是几个零碎的词，串不成句"**（见 A11） |
| 【你的行为】8 | （无） | **新增**："用户不想讲、或者没看懂，直接来问你的时候——**千万别推回去**" + 搭桥三步 + 收在"那你现在说说看？"（见 A9/A10） |
| 【你已经知道的】首条 | （无） | **新增最硬一条**："用户在问你事、或者向你求助的时候，先回应他，**绝对不许扯别的记忆**"（见 A12） |

**V0.2 的规矩保留不动**：禁 emoji、禁俚语、禁吐槽/抖机灵/发表评论、不硬造联想。

### 3.2 `app/web.py`（对话历史持久化，A15）

- 新增 `app/history.json`：`{ "<设备id>": {"topic": "<材料id>", "messages": [...]} }`
- 新增 `GET /api/history?device_id=X`
- `POST /api/chat`：**成功之后**才存历史（失败的轮次不污染上下文），每设备最多留 200 条
- 抽了通用的 `_load_json` / `_save_json`（原子写），记忆和历史共用

### 3.3 `app/static/index.html`（三处）

1. **开场白**（`opening()`）：有记忆时，随机挑一条学过的 + 5 种说法随机 → *"诶，你来了。上次你教我那个 Agent，我这两天还想着呢。"*
2. **面板分区标题**：「小问记住了」→ **「你教给她的」**
3. **面板每条加日期**（`niceDate()`）+ 她的一句开场 **"这些是你教我的。"**
4. **短名提取**（`shortName()`）：修 bug——原来标题是"大模型的「温度」是什么？"时，会抠出**整句**，导致开场白变成 *"上次你讲的「大模型的「温度」是什么」，我琢磨了好几天"*（嵌套引号，很蠢）。现在只取 「」 里的词 → `温度`
5. **恢复历史**：`boot()` 里拉 `/api/history`——有历史就**接着上次聊**（材料条回到上次那张、不重说开场白、材料条不自动摊开）；没历史才走开场白

⚠️ **副作用（已记录）**：因为"有历史就不说开场白"，**A6「她带着记忆开口」实际上只在"有记忆但历史被清空"时才会出现——基本等于废了**。需要的话另想办法保留（比如隔了较久才问候）。

## 关于联网搜索（A16）

**用户提议**："小问可以增加联网搜索功能……在用户搞不懂这东西的时候，小问就可以主动一些，给用户讲明白也未尝不可"

**调研结论：能做，但现阶段不该做。**

1. **截图里的问题不是缺联网** —— 她想答"向量是什么"，混元**本来就知道**。是提示词把她压死了（见 A13）。**松绑就够了，实测已通过**
2. **技术上不确定**：混元的联网能力（`EnableEnhancement` / `ForceSearchEnhancement`）在**原生接口**上，而"这些参数在 OpenAI 兼容接口里被过滤或忽略"；LobeHub 的记录显示兼容接口下 `search_info` 可能可用——**要实测才知道**，不保证
3. **对这个产品当前内容，联网收益低**：AI 名词是通识，模型都知道。联网真正有用的是**时效性内容**（热点、新闻）——而那属于 **V0.5 内容升级**
4. 建议：**留到 V0.5 一起做**。那时如果有"现象热点"类内容，联网就有真价值了

**真要做的话**：试 `search_info` 参数，实测是否生效（约 10 分钟）。

## 四、实测结果（2026-10-10）

**A2 门槛生效**：
```
讲得含糊 → "等下，'增强一下'是增强啥？……这步你跳过去了，我没接上。"   understood: false
讲得清楚 → 复述准确 + 追问                                          understood: true
```

**A5「用出来」生效，且没有过火**（3-4 次里触发 1 次）：
```
（记忆里有 RAG）讲幻觉 →
"哦哦我懂了——就是模型为了说得像真的，才一本正经编假话。
 上次你教 RAG 说找资料免得它瞎编，那瞎编原来就是说的这个啊。"
```

**③ 情绪"活一点"效果有限**：多了"等下""诶"这类起手，但反应仍偏淡。判断原因：被"1-3 句 + 必须推进对话"框住，情绪没地方放。**待用户手机体感确认。**

**A12「别答非所问」+ A9/A10「别推回去」生效**（用户手机截图暴露的问题，改完复测）：

```
（记忆里有 温度 和 RAG）
用户：微调是什么意思
```

## 流式输出（2026-10-10 已实现）

**改动**：`chat.py` 加 `chat_stream()` + `display_so_far()`；`web.py` 的 `/api/chat` 改成 SSE 分块返回；前端边收边渲染。

**难点**：两个隐藏标记要**边收边剥**——
- 开头的 `[懂了|总结]`：闭合前不能露出来
- 末尾的 `[递材料|id]`：边生成边来，得**扣住最后一个没闭合的 `[`**（否则用户会看到 `[递材料|tok` 这种半截标记）
- ⚠️ 顺带解决了 `苹果变 [1,0.8` 这种**正文里带方括号**的情况——扣住未闭合的 `[` 时它也会被暂扣，闭合后自动放出来

**⚠️ 但实测发现一个更硬的事实**：混元的瓶颈**不是生成，是首字延迟（TTFT）**。

```
首字到达 19.2s   ← 全卡在这
之后的 78 个字   0.6s 内全部到达
```

**所以流式治不了"等十几秒"**——那 19 秒是模型在憋第一个字，不是网慢也不是生成慢。
收益只有：长回复能看着它长出来，不是"啪"一下全出现。

**真正的解法是换个 TTFT 更低的模型**（当前 `HUNYUAN_MODEL=hy3`，走 tokenhub）。待试。
