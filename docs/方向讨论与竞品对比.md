> 记录：2026-10-09 ｜ 更新：2026-10-10（补第九节「界面：为什么记忆必须连界面一起改」）
> 用途：把产品想清楚（含走过的弯路）

## 一、讨论演进（弯路也记下来）

| # | 曾经的想法 | 问题在哪 | 纠正后 |
|---|---|---|---|
| 1 | 做语言表达助手，像刷抖音一样刷故事/名词 | feed 流的"爽"来自零投入，而"讲"要投入——**缝在一起用户一定会逃** | 想说就说，不想说就划走；一个话题=一张卡片 |
| 2 | AI 给用户的表达打分 | 打分=考试=压力，违背"轻松"基调 | 改成 **AI 复述确认**——复述对了=你说清楚了，复述偏了=没说清 |
| 3 | AI 是"检查员" | 有被评估感 | 改成 **AI 是不懂的朋友**——把"被评估"变成"被需要" |
| 4 | 内容丰富是护城河 | 用户不缺内容（B站/公众号/豆包），我们没有内容源优势 | 内容**不是**护城河，是"**勾人开口**"的启动器 |
| 5 | 长期记忆是差异化 | 豆包也有记忆，而且做得更好 | 记忆**不是**差异，"**记住你的表达成长**"才是 |
| 6 | 打怪升级 / 形象变大 | 游戏化会把轻松的事变成任务，**违背自己定的"不打卡"基调** | 改成"**他懂的每一样东西，都是你教的**"——用对话体现成长，不用数值 |
| 7 | 明说"师父/徒弟" | 刻意贴身份标签会显得假、有负担 | **不提身份**，靠对话行为让用户潜移默化感到"我在教她" |
| 8 | AI 说"以后看AI写的东西得留个心眼" | 吐槽、抖机灵，从"朋友"滑向"段子手" | 禁吐槽、禁网络俚语、禁 emoji；讲完必须**联想式反问**续话 |
| 9 | 做记忆 = 在现有卡片界面上加个记录 | 卡片=对话容器，一张卡就是一个独立会话 → 实测"**感觉像三个小问，每个小问记一个问题**" | 见第九节：**记忆没法只加功能，必须连界面一起改** |
| 10 | 点开讲过的材料时，她复述一遍总结 | 实测（用户手机截图）变成一串播报："这个你跟我讲过，我记着是…"，很吵 | 换材料**静默**；她的总结只出现在**听懂那一刻的复述**和**「小问记住了」面板**里 |

## 二、核心洞察（已定案）

1. **表达的本质是"被听懂"**，不是"说得漂亮" → 所以反馈机制是"换一个不懂的人来听"
2. **把"被评估"变成"被需要"** → AI 是听众，不是考官
3. **成长不需要进度条** → 徒弟会了，就是师父的成绩单
4. **不点明身份，让行为说话** → 不说"你是我师父"，而是用"记不住""又忘了""原来是这样"让用户自己感觉到

## 三、和豆包的对比（核心问题）

### 先承认事实

**把我们的系统提示词贴给豆包，效果能到九成。** 它是一段文字，谁都能复制，不是护城河。

### 那这个产品为什么还存在？

**类比：健身 App。** 你也可以自己看视频练，但还是会下载一个 App——因为它帮你规划、记录、追踪。

| 维度 | 豆包（通用助手） | 我们（练习场） |
|---|---|---|
| 角色 | 有问必答的**专家** | **不懂的人** |
| 用户位置 | 提问者、被服务者 | 讲的人、教的人 |
| 给用户的 | 答案 | **表达效果的验证**（我说明白了吗） |
| 记忆 | 记你的偏好（为了服务你） | 记你**讲过什么、讲得怎么样**（成长档案） |
| 关系 | 对所有人一样 | **只跟着你长大** |
| 使用方式 | 临时想起才用 | 有内容勾人、有连续性 |

### 豆包（及任何通用助手）结构上做不到的

1. **它的"懂"不是从你这学的** → 给不了"我教会了他"的成就感
2. **它是通用工具** → 每次都要用户自己搭场子（贴 prompt、设定角色），而且**每次归零**
3. **它是"问答"，不是"练习场"** → 没有内容入口、没有进步轨迹、没有连续的关系

### 诚实的风险

**这些差异加起来够不够撑起一个独立产品，还没验证。** 尤其"练表达"本身是弱需求——用户不会主动找。

所以产品成败的关键可能不在差异够不够锋利，而在：**能不能让"想讲两句"这件事自然发生。**

## 四、当前定案

### 角色设定

不提"师父/徒弟"，通过对话行为让用户感受到自己在教她：

| 场景 | 她说什么 |
|---|---|
| 第一次 | "你是……我好像不认识这个，你能给我讲讲吗？" |
| 学过一个概念 | "Agent 我记得！就是自己拆任务那个对吧？" |
| 学混了 | "我好像把 RAG 和幻觉搞混了……是不是这样的？" ← **用户会忍不住纠正她** |
| 很久没来 | "哎，你来了！"（**绝不提等了多久、绝不催**） |

### 铁律

**她永远在那儿，你来了她高兴，你不来她绝不打扰。**

只要她开始表达"失望"或"等待"，打卡就回来了，轻松基调就破了。

### 成长怎么体现

不用等级条、不用经验值。用**她的变化**：

- 她记得你教过什么（记忆）
- 她学混了、你来纠正（互动）
- 时间线："10月8日，你教会我什么是 Agent"（回忆）

## 五、待验证（按优先级）

| # | 要验证的 | 怎么验 |
|---|---|---|
| 1 | 第一次讲完，是"还可以"还是"想再来" | 连着讲三个概念，看第三个时还想不想讲 |
| 2 | "她记得你教过什么"能不能自然产生师徒感 | 记忆（V0.3）正在做；做完再真人验证 |
| 3 | 用户愿不愿意扮演"教的人"这个角色 | 直接问试用的人："你觉得自己在教她吗？" |
| 4 | 内容够不够勾人 | 数据：看到卡片后点"我也说说"的比例 |

## 六、已知的前提依赖

**记忆是"关系"的前提，不是可选项。**

- 第一次对话：靠"她不懂"就能产生教的感觉（无需记忆）
- 第二次以后：必须靠"她记得你教过什么"才能强化关系

→ 所以记忆的排期要往前挪（原定 V0.5，应提前到与试用验证同期）
→ **已落地**：排期到 **V0.3**（2026-10-10 设计定稿）

## 七、内容与产品的分工（想清楚的一条）

| | 作用 | 是不是护城河 |
|---|---|---|
| 内容 | **勾人开口**（看到就想说） | 不是，但是必要的启动器 |
| 记忆 | 让"成长"被看见 | 不是，但改造后（成长档案）是差异 |
| 复述确认机制 | 表达效果的验证 | **是**——通用助手结构上给不了 |
| 关系（她的变化） | 留存 | **是**——但依赖记忆 |

## 八、界面：为什么记忆必须连界面一起改（2026-10-10 补）

做 V0.3 时冒出来的一条，值得单独记。

### 起因

原本以为"记忆"是个可以往现有界面上加的功能——加个「她记住了」的标记就行。设计出来一测，用户（手机上）反馈：

> **"感觉像三个小问，每个小问记一个问题。"**

### 根因

界面是「三张卡，每张卡里装一段自己的对话」。**卡片一旦成了对话的容器，一张卡就是一个独立会话**——所以记忆也自然是三份，各记各的。

这跟产品要的东西**直接冲突**：我们要的是**一个**朋友，她记得你教过的一切。

### 纠正

| 从 | 到 |
|---|---|
| 卡片 = 会话容器 | **材料 = 她递给你的一张纸**（不是另一个她） |
| 三张卡，三段对话 | **一条对话**（换材料不清空） |
| 记忆挂在每张卡上 | 记忆是**小问的**，有一个统一的家（「小问记住了」面板） |
| 主界面铺全量材料 | **一次只露一张**，讲过的归入面板（列表长度与内容总量脱钩） |

### 结论

**"加记忆"这件事，本质是"把产品从'一堆卡片'改成'一个朋友'"。** 界面重构不是记忆的附带工作，它就是记忆本身。
