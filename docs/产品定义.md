# 讲给朋友听 · 产品定义

> 工作名（待定）｜ 创建：2026-10-08 ｜ 更新：2026-10-11
> 状态：V0.1–V0.5 已完成（V0.5 主体完成，待长期体感验证）

## 一句话

**让你把知道的事，讲给一个不懂的朋友听——他听懂了，你就讲明白了。**

## 一、它不是什么（定位差异）

| 市面口才训练 | 本产品 |
|---|---|
| 结构化训练、金字塔原理、万能模板、话术库 | **不教任何结构套路** |
| 打分：逻辑性 7 分、流畅度 6 分 | **不打分** |
| 任务感：每日打卡、训练计划 | **没有计划、没有打卡、没有欠债** |
| 练"怎么说得漂亮" | 练"**怎么让人听懂**" |

## 二、核心洞察

**表达的本质不是"说得对"，而是"被听懂"。**

所以反馈机制不该是评分，而该是——**换一个不懂的人来听，看他听没听懂**。

这就得到了产品最核心的设计：

> **AI 扮演一个不懂的朋友（不是考官），用户讲给他听。**

这一下同时解决了三个问题：

| 问题 | 怎么解决的 |
|---|---|
| 压力（不想被评价） | 对方不是考官，是个想听你说的人 → **"被评估"变成"被需要"** |
| 动机（为什么要讲） | "有人真心想知道"比"我要练口才"强一百倍 |
| 反馈（怎么知道自己说得好不好） | 他懂了没懂，你看得出来 → **不用评分，用户自己就知道** |

背后是费曼技巧：**教别人是学得最快的方式**。不需要让用户"练表达"，让他"讲给一个不懂的人听"就够了。

## 三、完整流程

```
① 浏览卡片        刷到一个话题，看一眼内容，了解个大概
② 想说就说        点「我也说说」进入对话；不想说就继续划走
③ 讲              用自己的话讲给朋友听
                  ↕ 随时可以回头看内容（"我忘了，再看看"）
④ 朋友追问        没听懂就问 → 用户换种说法 / 打比方 / 举例
⑤ 收尾            用户讲完，朋友复述确认："哦哦我懂了，就是……"
⑥ 又抛回来        朋友补一句，鼓励用户再讲一遍（可选，可跳过）
⑦ 彩蛋（可选）    朋友："那我也说说我的看法……" → 变成讨论
```

### 关键：说/看两条路自由切换

- **只看**：纯了解知识，零压力，划走就走
- **想说**：随时按「我也说说」，说完就走，不强制继续

**"想说就说，不想说就划走"**——不设打卡、不设计划、没有欠债感。这是轻松基调的来源。

> ⚠️ **V0.3 更新**：上面这套"卡片 → 点我也说说 → 进对话"的交互**已废弃**。
> 新界面没有"进入对话"这个动作——对话**一直都在**，材料只是它上面的一条带子。
> 原因见 [prd/V0.3-记忆.md](prd/V0.3-记忆.md)：「把对话装进卡片」会长成"三个小问，各记各的"，
> 与"一个朋友记得你教的一切"直接冲突。核心机制（讲 → 追问 → 复述确认）没变，变的是它长在哪儿。

## 四、AI 朋友的行为设定

**人设**：好奇的、不太懂这件事的朋友。**不是小白，也不装傻。**

| 要 | 不要 |
|---|---|
| 有反应："啊？还能这样？" | 客服腔："请继续说明。" |
| 有情绪："这么麻烦啊" | 考官腔："你的表达很清晰。" |
| 会猜："我猜是不是……？" | 被动等喂："然后呢？" |
| 追问具体位置（见下） | 笼统说"没懂" |
| 短句（1-3 句） | 长篇大论 |

**追问必须具体**：
- ❌ "我还是不太明白"（用户不知道补哪里）
- ✅ "前面都懂了，就是'它能自己拆任务'那句——它怎么知道该拆成几步？"

**"听懂了"要诚实**：
- AI 假装不懂拖长对话 → 用户察觉被套路
- AI 假装懂了 → 用户没收获，产品失去价值
- **门槛不要过高**：不要求用户说得精准凝练。AI 可以"哦哦我懂了，就是……"**帮用户把最后没说明白的部分补出来**——这既是"被理解"的爽感，也是一次表达示范

**兜底（讲几遍都不懂怎么办）**：AI 不能干听，要参与进来——
> "这样吧，我先说说我理解的，你看哪不对——你说 Agent 会自己拆任务，我理解就像一个包工头，接到活儿自己分给底下人？"

角色反转，用户从"我要讲明白"变成"我来纠正你"，压力归零，话自然就多了。

## 五、输入方式

**双模式，语音优先**：能说就说，不方便就打字。

- 练的是"说"，所以语音是默认
- 但宿舍有室友、在图书馆——**不能因为场合问题让用户掉线**
- 附赠设计：**把用户说的转成文字显示**。很多人不知道自己有多啰嗦、重复了多少次——看到自己的话，是最直接的自我觉察，不需要评分

## 六、内容策略（MVP 范围）

| 类型 | 状态 | 说明 |
|---|---|---|
| **AI 名词** | ✅ 第一版做 | 问法朴素（"什么是 Agent"），**先跑通机制** |
| AI 名词 · 情景导入 | 💡 后续优化 | 如"Claude Code、Codex 都叫 Agent，那 Agent 到底是什么意思呢？"——用悬念代替直白提问 |
| 小故事 | ❌ 暂不做 | 纯复述没有对话互动，与核心机制不搭（未来可改造为带互动的版本） |
| 现象热点 | ⏸️ 后续再做 | 要结合现实事件，如"高铁票该不该支持两人三座" |

**MVP 要验证的是"机制"不是"内容吸引力"**：
1. 用户愿意对着 AI 讲吗？
2. AI 追问，用户会继续说吗？
3. "他听懂了"那一刻，用户有成就感吗？

## 七、待验证的假设（跑 demo 后重点看）

- [ ] "讲给不懂的朋友听"是否真的让人放松（而不是换了个形式的压力）
- [ ] AI 追问会不会让人烦（追问频率、追问位置对不对）
- [ ] "他听懂了"的瞬间，成就感是否成立
- [ ] 回头看内容的设计，是减压还是干扰
- [ ] 语音 vs 打字，用户实际会选哪个

## 八、长期方向（已记录，后期再做）

### 动机层：有人真心想知道

产品的动力不来自"我要练口才"，而来自**"有人真心想知道"**。这一点是整个设计的根，后面所有功能都要服务它、不能削弱它。

### 回忆：让"被听过"累积起来

后期加入**回忆**能力——记录并回看：

- 哪年哪月哪日，我们讨论了什么
- 你讲的，我听懂了什么
- 我们一起聊过什么

**价值**：单次"被听懂"是当下的爽感，累积起来就变成了"有人一直听我说话"——这是留存机制的自然答案（而不是打卡）。

> ✅ **V0.3 落地了第一步**：她记得你教过什么——每个讲过的材料上留一句"她听懂的那句话"，
> 归在「小问记住了」里。时间线（"10月8日，你教会我什么是 Agent"）留到后面。

### 关系：让她慢慢"被你教会"

**不点明"师父/徒弟"这层身份**——刻意贴标签会显得假、有负担。靠对话行为让用户潜移默化感到"我在教她"：

- 她记不住 → 用户解释 → 表达练习
- 她学混了 → 用户纠正 → 比复述更自然
- 她引用"你上次教我的" → **关系成立**

**铁律：她永远在那儿，你来了她高兴，你不来她绝不打扰。**
只要她开始表达"失望"或"等待"，打卡就回来了，轻松基调就破了。

**成长不用等级条、不用经验值**——用她的变化来体现。她懂了，就是用户的成绩单。

详见 [方向讨论与竞品对比.md](方向讨论与竞品对比.md)。

### 终局：转向「长期陪伴的、聊兴趣的朋友」

长期看，产品会从"讲给朋友听"这个练习场景，长成一个**陪聊兴趣点的朋友**：
用户讲他感兴趣的东西，朋友听、追问、联想、记得住，一来一回能聊很久。

"讲明白"是入口，"有个人一直在"是终点。
